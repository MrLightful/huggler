## Desktop General settings

Steer uses Codex 0.170.0’s native `turn/steer` over app-server stdio when a turn can accept text. Messages with attachments and follow-ups without an eligible Codex turn use the existing queue. ## Desktop conversation checkout

Desktop saves reusable local Git checkouts and their display names in preferences and lets either conversation creation view search and select them. T3 Code stores its project catalog on the environment server and passes a scoped project reference into draft creation. Huggler Desktop resolves the selected checkout through the existing Rust project and workspace APIs when it opens the conversation. [T3 Code draft selection](https://github.com/pingdotgg/t3code/blob/338352dee2f43079482e054e8229a2ba055641d9/apps/web/src/hooks/useHandleNewThread.ts) · [Desktop workflow](https://github.com/MrLightful/bear/blob/main/docs/desktop-coding.md) · [Saved-project workflow check](https://github.com/MrLightful/bear/blob/main/scripts/check-desktop-settings.py)

Desktop owns the workspace mode and the searchable branch picker. It follows T3 Code's rule that a default worktree base must resolve to a commit. Desktop reads Git's cached remote default at launch, prefers `origin` when present, and falls back to `main`, `master`, the current commit, or another available branch. The worktree picker includes local and remote-tracking refs. **Current checkout** uses the chosen directory and can switch to a selected local branch at launch. Git refuses switches that would overwrite local files or use a branch checked out in another worktree. A repository without a base commit falls back to **Current checkout**. Remote-tracking refs reflect the last Git fetch. [T3 Code default branch regression](https://github.com/pingdotgg/t3code/commit/bc7fe11002aaa29a98d7429eb765765bc366b59d) · [Desktop workflow](https://github.com/MrLightful/bear/blob/main/scripts/check-desktop-coding.py)

The Rust allocator resolves the chosen ref to an immutable commit before reserving a managed checkout. Desktop derives a title locally from the first message and passes it to the allocator for a readable, unique branch and directory. It can also pass an exact branch name. Desktop shows setup progress through base selection, checkout creation, and conversation opening. T3 Code uses its configured text generation provider to name the branch before agent startup and handles title generation separately. The desktop check uses a scripted Codex app-server peer over stdio and verifies the title, checkout path, branch and starting commit. ## Conversation titles

The host supplies the immediate title at launch and decides when to ask for a suggestion. A Rust host can call [`generate_conversation_title`](../src/providers/codex/text_generation.rs) with the first user message or, for regeneration, a transcript and the previous title. The caller chooses the model and supplies any project name, preferences, or context from attachments and links. A missing suggestion or provider error leaves the immediate title available. The host can apply a suggestion with [`Huggler::set_thread_title_if_current`](../src/runtime.rs), using a snapshot from `Huggler::thread_title`. It checks the title revision, publishes the new name in snapshots and events, and preserves conversation ordering. This title update does not rename the checkout or its branch.

The Codex adapter uses an isolated, ephemeral app-server turn over JSON-RPC stdio with a structured title result. This is a Huggler fallback implemented with the native turn protocol. Other adapters have no built-in title generator. The [Codex 0.170.0 capture](../tests/fixtures/title-codex-0.170.0.ndjson) records the structured response from a hosted title turn. The [scripted peer](../tests/fixtures/title-codex.py) replays it for the [Rust consumer check](../tests/conversation_title.rs), which also covers regeneration, stale updates, and persistence. T3 Code's automatic scheduling and transcript or link lookup remain host decisions in Huggler. The port includes the [project name omission](https://github.com/pingdotgg/t3code/commit/c092c6eb1e91772e93f0956a5fa6c855d62aa51e) and [custom title preferences](https://github.com/pingdotgg/t3code/commit/760f9cbe64e3409a7ebcc1ec16debe31a61e9f2b) prompt behavior. [Upstream title service](https://github.com/pingdotgg/t3code/blob/d023407be83f50b37493ea3dc5f33e109138ac8f/apps/server/src/orchestration-v2/ThreadTitleRegenerationService.ts) · [Upstream regression](https://github.com/pingdotgg/t3code/blob/d023407be83f50b37493ea3dc5f33e109138ac8f/apps/server/src/orchestration-v2/ThreadTitleRegenerationService.test.ts)

## Desktop pull request actions

Desktop owns the header action and bundles the PR-writing skill. **Create PR** enqueues an ordinary turn in the current conversation, behind any active turn and work already ahead of it. That turn uses the selected provider and model to write a title and description from the branch changes and available verification. Desktop embeds the skill instructions in the queued request for delivery through the provider’s normal message transport. The agent calls Bear’s publisher, which validates the checkout and draft snapshot, commits pending changes, pushes the branch, and sets its upstream when necessary. The shared GitHub repository client reads the base branch and PR status and submits the creation request. It also revalidates the PR, base branch, head commit and allowed operation before asking GitHub to merge, enable auto-merge or enqueue. GitHub enforces the expected head commit during those updates. **Fix** and **Resolve** also use the conversation queue. [Shared GitHub operations](../src/repository/github.rs) · [T3 Code commit, push and PR workflow](https://github.com/pingdotgg/t3code/blob/338352dee2f43079482e054e8229a2ba055641d9/apps/server/src/git/GitManager.ts)

The desktop qualification uses a bare Git remote, a scripted GitHub CLI credential, a local GitHub API fixture, and an unversioned scripted Codex app-server peer over stdio. It observes the native queued turn before allowing the active turn to make its final edit. The PR payload uses the draft’s title and description, and the published commit includes the active turn’s final edit alongside staged, unstaged, new, and deleted files. The fixture also covers a branch switch, invalid draft input, file changes during drafting, a rejected commit hook, an ahead branch, and recovery after a lost creation response. A compare link is the fallback for synced, clean branches when GitHub status is unavailable. ## Desktop terminal

On macOS, the desktop owns an interactive terminal under **All files** and **Changes**. Opening the pane for the first time starts a login shell in the conversation’s checkout. Each conversation can open several terminal tabs with independent shells and scrollback. Switching tabs or conversations or collapsing the pane preserves those sessions until the app quits. Resizing the pane updates the active shell’s PTY dimensions. Users can close individual tabs or restart an exited shell in its tab.

T3 Code pairs its Ghostty WebAssembly surface with a server-side `node-pty` adapter. Huggler uses GPUI, statically linked `libghostty-vt` 1.0.1, and `portable-pty` in the macOS desktop process. Huggler renders one tab at a time with in-memory scrollback and text cells. Split terminal groups, persisted history, remote terminals, and inline graphics are outside this implementation. The desktop check drives the real sidebar, tabs, and shells in temporary checkouts. ### File attachments in Huggler

The desktop inserts an inline attachment pill at the composer cursor when you select or drop files or paste an image. The pill includes the file icon, a filename that truncates to fit, and a remove button. Backspace immediately after a pill also removes its reference from the draft. References stay in place in Backlog and become clickable chips in sent messages. Opening a chip displays its preview at that position in the message. Older messages without a reference show their chips after the caption. The desktop owns previews and saving a copy. The crate validates and stores the original bytes with the message, scopes upload claims to their thread, and keeps bytes out of history pages and replay events. Adapters choose how to deliver the files. Huggler uses bounded UTF-8 and PDF excerpts and local file paths for other formats. A configured external OpenCode server needs a shared filesystem for those paths to work. Portable fork summaries carry bounded message text.

| Harness and transport | Turn input |
| --- | --- |
| Codex app-server 0.170.0 over stdio | Native `localImage` for PNG, JPEG, GIF and WebP. PDFs use an extracted text excerpt and a local file path. |
| ACP v1/v2 over stdio, including Claude Agent | Native image content blocks when the harness advertises `promptCapabilities.image`. Local file paths provide a fallback. |
| Pi RPC 1.0.0 fixture over stdio | Native `images` on `prompt`. Other files use the text and path fallback. |
| Muse 1.4.3 JSON-RPC fixture over stdio | Native image parts on `turn/start` following the upstream Muse adapter. Other files use the text and path fallback. |
| OpenCode HTTP 1.14.39 and 2.0.18 fixtures | Managed v1 uses native image and PDF file parts. Managed v2 uses native image files and the text and path fallback for PDFs. External servers receive the text and path fallback. |

The desktop history check verifies picker and clipboard insertion between existing text and confirms that the unversioned Codex app-server fixture receives the reference in the prompt and a native image over stdio. The upstream reference is the attachment handling at `338352dee2f43079482e054e8229a2ba055641d9`, including the fix that keeps attachment references visible in the provider prompt. Huggler reads PDFs in Rust. Other binary documents use the original file path.
