Configure an instance with a Rust `Provider` variant or use the driver key below as a TypeScript instance’s `driver`. The matrix describes the underlying adapters. The host APIs for invoking their capabilities are listed in the [Rust reference](/reference/runtime-api/) and [TypeScript reference](/reference/typescript-sdk/). To discover what your installation supports, call `probe_provider` in Rust or `probeProvider` in TypeScript.

## Adapter settings and limits

- **ACP.** Pass provider-specific invocation arguments in `ProviderInstance.args`. Resume needs negotiated session loading, and agent tools need HTTP MCP support. Root interruption on managed stdio stops the provider process. Native child tracking and interruption are covered for Claude Agent and Codex.
- **OpenCode.** Managed mode starts a server and can register run-scoped MCP. Set `server_url` for an externally managed numeric loopback HTTP origin. Supply `password_env` to read its password from the named environment variable. External mode leaves MCP configuration and process lifetime with the host. Use one writer per native session. On 2.x, a disconnect between actual and observed inbox delivery can leave the prompt running on an external server.
- **Pi.** For agent tools, set `pi_extension` to the absolute path of the separate [Huggler extension](https://github.com/MrLightful/huggler/tree/master/adapters/pi). It runs inside Pi’s runtime. Pi cancels interactive extension dialogs.
- **Muse.** Use the provider’s MSP server configuration. An unsupported interactive request fails the turn.
- **Usage.** Rust’s `provider_usage` and TypeScript’s `readProviderUsage()` aggregate input and output tokens for reporting application runs, grouped by instance. Providers that omit usage contribute no report.

See [Configure providers](/guides/configure-providers/) for the registration and launch workflow.
