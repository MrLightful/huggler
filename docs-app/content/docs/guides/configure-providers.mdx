## Register an installation

A fresh configuration registers the built-in instances `codex` and `claudeAgent`. These look for `codex` and `claude-agent-acp` on PATH. The runtime validates the registry when it opens and checks provider startup and login when you probe or use an instance.

Add a named instance to use a separate account, executable, or configuration. Choose a unique ID of up to 100 ASCII letters, digits, periods, underscores, or hyphens. Specify an executable on PATH or an absolute executable path. Codex, Claude Agent, and Pi support absolute instance homes.

## Probe and select

1. Open the runtime and register the working tree where the agent will run.
2. Probe the instance with that working directory. Discovery can start the provider and may create an empty session for ACP model discovery.
3. Read the transport, version, models, and capabilities that discovery reports. An empty model catalog can still support the default model. Authentication can remain unverified after discovery.
4. Launch a thread using that instance ID and, optionally, a reported model ID. Keep the instance ID, executable, arguments, home, and server settings for native continuation.

## Diagnose discovery failures

| Symptom | Check |
| --- | --- |
| Executable missing | Install the CLI or update its configured executable path. |
| Login required | Sign in with the provider’s CLI using the instance’s configured home. |
| Server access denied | Check the external OpenCode server’s credentials and permissions. |
| Incompatible provider | Check the executable, invocation arguments, and negotiated protocol version. |

Find driver keys and adapter-specific settings in [Provider transports](/reference/providers/).
