## Enable agent tools

The host can make Huggler’s orchestration tools available to a provider that supports scoped MCP. Access is tied to the caller’s active run. Check whether the provider reports agent-tool support and whether your binding exposes the host controls. [Agent tool catalog](/reference/agent-tools/)

## Create independent peers

A peer is a separate thread with its own lifecycle. Peers can start with a prompt or stay idle. Sending to an idle peer starts a run, while sending to a busy peer queues the message. Delivery records the sender’s origin so the recipient can reply. Use peers when conversations should continue independently of the sender.

## Delegate owned work

Delegation lets a parent hand work to an owned child and receive its result. Choose the caller’s checkout or a separate worktree at its committed revision. The child may use a different configured provider instance.

A parent can wait for a result, a human approval request, or a timeout. It can also continue immediately and receive the result when it becomes idle. A parent can cancel the work in its delegated subtree. Keep the same request identity when retrying a delegation.

## Observe provider-native child sessions

Some agents create their own child sessions within a Huggler run. Those sessions have provider-issued identities and can remain active after the application turn finishes. Use the stored task and native-child state to show the distinction in your host.
