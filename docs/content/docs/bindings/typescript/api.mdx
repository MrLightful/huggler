Import `Huggler` and the ID helpers from `@huggler/sdk`. The package includes TypeScript declarations and supports ESM and CommonJS. Each runtime method returns a promise. [Install the preview and run a turn](/bindings/typescript/quickstart/)

## Open and configure

```typescript
const host = await Huggler.open({ name: "Studio Workbench" })
```

Huggler derives a slug from the display name by lowercasing ASCII letters and joining words with hyphens. Pass `slug` to set it explicitly. The slug is the provider and MCP identifier and supplies the default directory `~/.<slug>`. It accepts 1–128 ASCII letters, digits, underscores, or hyphens. In the default directory, the database lives in `userdata/huggler.sqlite3` and managed checkouts in `worktrees/{id}`.

| `Huggler.open(options)` field | Purpose |
| --- | --- |
| `name` | Display name. Defaults to the supplied slug, or `Huggler` for path-only configurations. |
| `slug` | Optional explicit identifier used for provider connections, MCP registration, and the default state directory. Supply at least one of `name`, `slug`, or `stateDir`. |
| `stateDir` | Choose the base directory. When supplied, the database defaults to `huggler.sqlite3` directly inside it. |
| `instances` | Additional named provider installations. Each needs an `id`, `driver`, and `executable`. Launch accepts the built-in IDs `"codex"` and `"claudeAgent"` or a registered ID made with `providerInstanceId()`. |
| `storage` | Override `databasePath` or configure the worktree layout. Threads launched through the preview run in the registered project's root checkout. |
| `output` | Advanced overrides for how Huggler and its tools appear to providers and agents. |

```typescript
const host = await Huggler.open({
  name: "Studio / Lab",
  slug: "studio_lab",
  stateDir: dataDirectory,
  storage: { databasePath: "sessions/history.db" },
})
```

### Provider and agent presentation

- `output.name` overrides the provider client identifier and MCP registration key. Keep this key stable for providers that store permissions under it.
- `output.title` overrides the display name seen in supported provider metadata and generated conversation text.
- `output.version` overrides the version advertised in provider and MCP handshakes. It defaults to the Huggler runtime version.
- `output.instructions`, `providerLabels`, and `tools` customize MCP instructions, provider labels, and advertised tool names, titles, or descriptions.

## Run a conversation

| Call | Result |
| --- | --- |
| `openProject(path)` | Registers a Git working tree and returns its `id` and canonical `root`. |
| `listProviderInstances()`, `probeProvider(instance, cwd)` | List configurations or check one provider's transport, login status, models, and capabilities. |
| `launch({ commandId, threadId, projectId, providerInstanceId, name, model })` | Creates a thread. Omit `model` for the provider default. |
| `send({ commandId, threadId, text, mode })` | Starts a turn on an idle thread and returns a receipt with `runId` and `messageId`. Omit `mode` for an ordinary send or pass `"plan"` for Codex plan mode. |
| `wait(threadId, runId, { signal })` | Resolves to a terminal run. Inspect `status` for `completed`, `interrupted`, or `failed`. The options argument is optional. Aborting the wait detaches that observer. |
| `stopThread({ commandId, threadId })` | Requests interruption and returns a receipt. |
| `respondToPermission({ threadId, runId, requestId, option })` | Submits an offered option ID for a pending permission. |
| `respondToQuestion({ threadId, runId, requestId, answers })` | Submits answers keyed by question ID. Each value is a string or an array of strings. |
| `close()` | Shuts down the runtime and releases database ownership. Await it before reopening the database in any host. |

Use `threadId("…")` and `commandId("…")` for application-owned IDs. Save command IDs with their payloads so a retry can recover the original receipt. Pass IDs returned by the SDK directly to subsequent calls.

## Observe and read

| Call | Result |
| --- | --- |
| `subscribe(threadId, { after, signal })` | Returns `{ snapshot, events }`. With no options, the async iterator starts after the snapshot. A supplied cursor replays strictly after that position. Read `event.change.type` to distinguish changes and `event.sequence` to save a replay cursor. |
| `listThreads()`, `readThread(threadId)` | List thread IDs and names or read one full snapshot, including messages, runs, pending requests, and the event cursor. |
| `readHistory(threadId, { before, query, limit })` | Returns conversation details with a bounded `history.messages` page. Options are optional. Use `history.older` for the previous page. |
| `readMessage(threadId, messageId)` | Loads the full message when a history preview is truncated. |
| `readProviderUsage()` | Returns reported run and token totals grouped by provider instance. |

Keep cursors and 64-bit counts as strings across storage and serialization. See [Manage history and context](/bindings/typescript/history-and-context/) for paging and [Durability and recovery](/concepts/durability/) for replay after a restart.

## Handle errors

Catch `HugglerError` and check `error.code`. For `busy`, inspect the foreground run before submitting again. For `conflict`, `error.detail.originalThread` and `error.detail.requestedThread` identify where a command ID was reused. For `cursor_expired`, rebuild the view with a fresh subscription. For `history_changed`, restart the history query from its first page.
